Audit rules

The list of 202 rules the site audit checks. For each rule you find what it means and how to fix it.

The site audit checks every page, and the site as a whole, against 202 rules: 13 critical, 93 warnings and 96 info. That is the number of rule IDs in the app's rule list, and each one is a row in the tables below. Critical (13 rules): Google cannot see or understand the page, or visitors cannot reach the site, so fix these first. Warning (64 rules in that table): they slowly lower rankings and clicks. Info (62 rules in that table): small opportunities to improve. The Additional checks section below lists 63 more rules (29 warnings, 34 info). In the score, critical counts 40, warning 15 and info 3, and the number of pages a rule affects counts too.

The table gives the rule name shown on screen, what it means and the first step to fix it. The full fix text is on the finding card on screen. The last column is the rule ID, which shows up in the CSV file and in assistant answers.

Common terms

  • canonical: a way to tell Google "this is the main address".
  • noindex: a tag that hides a page from search.
  • hreflang: the language version tag. It points to the same page in other languages.
  • meta description: the gray summary under the title in a search result.
  • structured data (JSON-LD): a hidden note that tells Google what the page is (a product, an article and so on). It can add extras to the search result, such as stars or an image (rich result).
  • robots.txt: the file that tells Google which pages it may visit. A "Disallow" line forbids access.
  • sitemap: the list of pages on your site. lastmod: the date the page last changed.
  • redirect: sending visitors from one address to another.
  • user agent: the name a browser or crawler gives itself.
  • title (title tag): the title shown in the tab and in search. H1: the main heading of the page. alt text: a short text that says what an image shows.
  • nofollow: a tag that says "do not follow this link". head: the top part of the page source.
  • LCP: how long the main content of the page takes to appear. CLS: content shifting while the page loads. INP: how long the page takes to respond to a click.
  • Lighthouse: Google's page-testing tool. SSL certificate: the document that makes your site https (a secure address).

How do the rules work?

Most rules run per page and list every page they affect. Some concern the whole site and produce a single finding. These are the robots.txt rules, the sitemap rules, "Site has no social media sharing tags" and "Site has no structured data at all".

Rules whose name starts with "Google" do not come from the app's crawl. They are produced from the answers taken from Google on the Index status tab. If you have never asked a question on that tab, these rules never run. The speed rules (LCP, CLS, INP, SEO score) run only when "Also measure page speed" is on, and they use the phone measurement.

Some rules don't look at pages one by one: they probe the site once at the start of the audit and produce a single finding. These cover the www and non-www addresses, the http-to-https redirect, the answer to a random address that doesn't exist, robots.txt closing the whole site, its sitemap line and AI bots, the site icon, llms.txt, security headers (HSTS, X-Content-Type-Options, frame protection, Referrer-Policy), and the start page's size, compression and first response time. The SSL certificate's expiry date is read from public certificate logs (Certificate Transparency), the domain's from the domain registration data (RDAP), and the SPF and DMARC records from DNS. "Analytics id on the pages doesn't match the connected property" compares the measurement id on the pages with the ids of the Google Analytics property connected to the project.

Rules whose ID starts with "lh-", and the "needs improvement" rules for LCP, CLS and INP, are read from the Lighthouse report PageSpeed Insights already sends for each page; they run only when "Also measure page speed" is on, and use the phone measurement. An audit Lighthouse didn't run or failed on a page is neither a finding nor a pass. "A link to another site is broken" and "Image file is too large" run only when "Also check outgoing links and image sizes" is on at launch: after the crawl, at most 300 addresses are requested. Sites that block bots, such as social networks, and addresses that don't answer are never counted as broken. A rule an audit didn't measure shows as "unknown" in the Checks tab, including on audits made before these rules were added.
