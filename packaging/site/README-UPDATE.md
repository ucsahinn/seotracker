# seowatcher.io site update — 0.8.5 Alpha (2026-10-29)

This updates the already deployed seowatcher site to 0.8.5 Alpha. Guide prefixes and page names use each edition's own language, for example `/kilavuz/analitik/`, `/de/dokumentation/datenanalyse/`, `/fr/guides/statistiques/`, `/it/guide/analisi/`, and `/pt/guias/analise/`. Earlier guide paths and privacy aliases receive single-hop HTTP 301 redirects, with noindex HTML refresh pages retained as a fallback. The updater installs the generated redirect snippet; it does not edit vhost files, certificates, DNS, application data, or other vhosts.

## Contents

- `site.tar.gz`: the six-language static website, assets, localized guides and old-path aliases.
- `update-seowatcher-site.sh`: validates the existing installation, active HTTPS include and archive, installs the release and redirect snippet, runs `nginx -t`, switches `/var/www/seowatcher/current`, and reloads nginx. On failure it restores the previous snippet and, if switched, the previous release symlink. It keeps the prior release for manual rollback.
- `seowatcher-redirects.conf`: generated by `pnpm run site:build` from the fallback alias inventory. Exact-match 301 locations cover every former guide and privacy route, including slashless and `index.html` forms. Include this file in `SHA256SUMS.txt` along with the archive, updater and README when preparing a bundle. The old `privacy-redirects.conf` is superseded.
- `SHA256SUMS.txt`: hashes for the files in this package.

The site contains 287 HTML files, including 142 refresh aliases, and 144 canonical sitemap URLs (plus the 404 page). The redirect snippet contains 426 exact locations. The six audit guides and 0.8.5 release notes agree with the app's 202 audit rules. The existing installation script from the older 0.5.0 package is first-install-only and must not be rerun on this server.

## Upload and verify from Windows PowerShell

Upload the update bundle files to a new staging directory on the VPS. The
bundle manifest checks the site archive and each helper file before the updater
can switch the live symlink:

```powershell
$bundle = "C:\Users\ulasc\Desktop\seotracker\dist\hetzner-site-update-0.8.5-alpha-20261029"
$server = "ulas@94.130.129.213"
ssh $server "mkdir -m 700 -p /home/ulas/seowatcher-update-085"
scp "$bundle\site.tar.gz" "$bundle\README-UPDATE.md" "$bundle\update-seowatcher-site.sh" "$bundle\seowatcher-redirects.conf" "$bundle\SHA256SUMS.txt" "${server}:/home/ulas/seowatcher-update-085/"
ssh $server
```

On the VPS, verify the uploaded bundle and review the updater before running
anything with sudo:

```sh
cd /home/ulas/seowatcher-update-085
sha256sum -c SHA256SUMS.txt
bash -n update-seowatcher-site.sh
less README-UPDATE.md
```

The updater expects the already configured `/var/www/seowatcher/current` symlink, enabled `seowatcher.io` nginx vhost and Let's Encrypt certificate for both apex and `www`. Complete the one-time include step below before the first update using this bundle format. If the active HTTPS block lacks the include, the updater prints the exact line and stops before installing the snippet or switching releases. Review the script, then run:

```sh
sudo bash ./update-seowatcher-site.sh
```

Success prints `SEOWATCHER_UPDATE_OK`. The prior release remains in `/var/www/seowatcher/releases/` for rollback. The script does not delete releases or alter the nginx vhost/certificate. A release directory already present causes a STOP; never overwrite it. Prepare a new reviewed release directory name for a subsequent update.

## One-time: include the generated HTTP redirects

Review `seowatcher-redirects.conf`, then install it before adding an nginx include, so `nginx -t` never sees a missing file:

```sh
sudo install -d -m 755 /etc/nginx/snippets
sudo install -m 644 seowatcher-redirects.conf /etc/nginx/snippets/seowatcher-redirects.conf
```

Back up `/etc/nginx/sites-available/seowatcher.io.conf`. Inside each active HTTPS `server` block whose `server_name` includes `seowatcher.io`, add exactly this line:

```nginx
include /etc/nginx/snippets/seowatcher-redirects.conf;
```

Remove any old inline privacy redirects or `privacy-redirects.conf` include from that same block to avoid duplicate exact locations. Leave all other vhosts alone. Run `sudo nginx -t`, and reload only if it succeeds; otherwise restore the vhost backup and any previous snippet before retrying. Later updates install the new snippet automatically and validate it before switching the site. English and Italian retain `/privacy/` as their canonical route.
